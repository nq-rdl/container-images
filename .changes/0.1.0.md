* UBI9 jamovi stack — r-base-ubi9 (Posit R 4.5.0, the rstudio/r-base equivalent), jamovi-deps-ubi9 (~200 CRAN packages), and jamovi-ubi9 (jamovi v2.7.30 server) — chained via docker buildx bake. UBI9 lacks flexiblas-devel/protobuf/boost, so the chain enables EPEL + AlmaLinux 9 at priority=200 (UBI/Red Hat packages always win). Also: validate-base-pins logs in to GHCR so a brand-new chain bootstrap-SKIPs reachability instead of failing on DENIED.
* Add scripts/repin-chained-base.sh — a fail-closed repin tool for chained-image BASE_CONTAINER digests. Implements guard-consistent error-class discrimination (MANIFEST_UNKNOWN bootstrap-SKIPs; DENIED/network/malformed-output fail-closed with non-zero exit), digest-format validation, path normalisation, and automatic BOOTSTRAP PLACEHOLDER comment replacement on repin. Adds offline hermetic test coverage (tests/test-repin-chained-base.sh) wired into pyproject.toml tasks and validate-base-pins.yml CI. Documents the chained-image bootstrap-and-repin workflow in CONTRIBUTING.md.
* Add GitHub-native provenance and SBOM attestation (actions/attest-build-provenance@v4 + anchore/sbom-action@v0 CycloneDX + actions/attest-sbom@v4, each with a one-shot Sigstore/Rekor retry) for all four datascience bake-published images: docker-stacks-foundation-ubi9, base-notebook-ubi9, minimal-notebook-ubi9, scipy-notebook-ubi9. Every image-publishing CI job is now attestation-gated — the temporary known-gap allowlist for the datascience bake job is gone, and `gh attestation verify` works for the whole catalog.
* Add go-ubi9 image: Go toolchain on UBI9-minimal for CGO_ENABLED=0 static builds (resolves #57)
* Add nginx-ubi9 image: non-root nginx SPA/static-file server on UBI9-micro, :8080 (resolves #58)
* Add proxy-ca-probe-ubi9 amd64 diagnostic image for the issue #59 proxy + CA-trust contract

* PR-driven release flow — the "Release — Prepare PR" workflow (workflow_dispatch) batches the changelog and stamps VERSION into a reviewable `release/v*` PR, a PR guard enforces monotonic versions, and merging it tags `v<version>` and publishes the GitHub Release
* datascience-notebook-cuda: public sensitive-free CUDA 12.6 + pytorch-gpu base for downstream GPU notebook overlays (Ubuntu-based on the digest-pinned upstream jupyter base; UBI rebuild is future state)
* Changie fragment length lint: 200-char body cap in .changie.yaml, enforced by changelog-check.yml, the `changie fragment length` pre-commit hook, and `pixi run lint-changie`
* Weekly `Changie pin check` workflow opens a `changie-pin` tracking issue when release-prepare.yml's Changie pin falls behind upstream's latest release (notify-only)
### Changed
* Updates `bun-ubi9` to Bun 1.3.14 — parses text `bun.lock` (`lockfileVersion: 1`) that 1.1.42 could not (#39)
### Fixed
* Build workflow now applies semantic version tags from image.yaml instead of only SHA-based tags
* Fix heredoc EOF delimiter error in build workflow caused by command substitution stripping trailing newlines from tag values
* Remove non-standard SHA and schedule tags from build workflow, use OCI 1.1 referrers for cosign to stop polluting the packages page with .sig/.att sidecar artifacts
* Set COSIGN_EXPERIMENTAL=1 for cosign sign and attest steps to support oci-1-1 registry referrers mode
* Disable built-in provenance/SBOM on build-push-action to eliminate `sha256-*` ghost tags from BuildKit referrers fallback
* Replace cosign sign/attest with GitHub-native attestation to eliminate `sha256-*` ghost tags from GHCR
* Stop pushing attestations to GHCR (push-to-registry: false) to eliminate sha256-<digest> referrer tags; attestations remain verifiable via the GitHub attestation API (gh attestation verify --repo).
* Eliminate GHCR orphaned-manifest churn at the source: digest-pin all base images, rebuild only on merged commits (no daily cron), add a FROM-aware base drift-checker, scan every published tag in the Trivy rescan, and add a reachability-safe one-time purge — superseding the scheduled cleanup janitor (#36).
* Build Images CI: attest a CycloneDX SBOM (~10 MiB) instead of SPDX (~17 MiB) so the StarRocks allin1 image stays under actions/attest-sbom's 16 MiB cap, and retry build-provenance/SBOM attestation once on transient Sigstore/Rekor errors (e.g. "error creating tlog entry").
* Repin the UBI9 datascience chain (base-notebook, minimal-notebook, scipy-notebook) BASE_CONTAINER digests to their published GHCR images, and add a crane-based reachability guard (pixi task policy-check-chained-bases-reachable + validate-base-pins CI) asserting chained base pins resolve in GHCR and cover declared platforms.
* Repin jamovi chain BASE_CONTAINER digests from bootstrap placeholders to the published GHCR digests (jamovi-deps-ubi9 -> r-base-ubi9@sha256:d454f816…, jamovi-ubi9 -> jamovi-deps-ubi9@sha256:aab6ae58…), restoring the digest-pin reproducibility guarantee — the chained-bases reachability guard now PASSES for all five pins (0 bootstrap skips).
* Hardened release workflows: canonical SemVer (no zero-padding), fail-closed remote probes, a global finalize FIFO queue, self-cleaning Prepare, SHA-pinned actions, Changie pinned at v1.26.0
* Unblock the conftest UBI-base policy: waive the datascience-notebook-cuda vendor base via a documented, tested `non_ubi_base_exceptions` allowlist (migration tracked in #84)
